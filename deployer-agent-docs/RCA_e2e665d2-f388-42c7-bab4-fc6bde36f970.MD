## 4) Code‑only rollback without overwriting production data
- **Yes, possible.** A Rollback re‑uses an already‑built earlier image (e.g. previous run `6cc7982e` / sha256:fe03a307…) rather than building/migrating. Database **data migration only happens on an initial deploy**; redeploys and rollbacks do **not** migrate or overwrite the production DB. So rolling the application code back to the prior version leaves the production database untouched.
- Caveat to flag to the owner: a rollback only reverts *code*. If the newer code performed any data/schema changes in the DB after going live, those data changes remain (rollback does not undo data writes). The DB itself is not wiped or replaced.
